# Contributing to Escala Tokens

Thanks for being here. This is a token generator whose whole job is to emit one
payload that Figma, CSS, and coding agents all read the same way. That makes
output stability the thing we protect hardest — most of the rules below exist
because a change that looks cosmetic can silently move a hex value or break a
consumer downstream.

## Getting set up

```bash
npm install     # postinstall generates the icon catalog — do not skip it
npm run dev
```

`npm install` runs `scripts/fetch-untitled-icons.mjs`, which builds
`src/generated/untitled-icons.ts` from the pinned `@untitledui/icons` package.
That file is **gitignored on purpose** — Untitled UI's license lets us use the
icons in a product but not redistribute the glyph set. Never commit it. `predev`
and `prebuild` regenerate it, so a fresh clone works from either entry point.

## Before you open a pull request

```bash
npm test        # Vitest, node environment
npm run lint
npm run build   # tsc -b && vite build
```

Run them in that order, and **do not treat a green `npm test` as sufficient.**
`npm run build` typechecks the test files via `tsconfig.test.json`; `vitest`
does not. It is entirely possible to have passing tests that fail the build.

If you touched the CLI, also run `npm run build:cli` and smoke it:

```bash
npm run cli -- --help
```

## Rules that will get a PR sent back

**Do not hand-edit `src/lib/color/*Reference.ts`.** `radixReference.ts` and
`tailwindReference.ts` are generated by `npm run gen:radix-reference` and
`gen:tailwind-reference`. They are committed so the runtime carries no
dependency on the vendor packages. They hold third-party data verbatim (see
`NOTICE`); editing one by hand makes it no longer that vendor's palette, which
is the only reason it exists.

**Do not run `vitest -u` without reading the diff.** Snapshot tests here guard
generated ramps. An updated snapshot is a claim that the new colors are more
correct than the old ones, and it needs to be argued for in the PR description,
not absorbed silently.

**One contrast implementation.** `src/lib/color/apca.ts` is it. Do not add a
second WCAG or APCA implementation in a skill, an MCP tool, or a checker, and
never use `chroma.contrast` on a hex value.

**The color layer is DOM-free.** Vitest runs in the `node` environment. Nothing
under `src/lib/color/` may reach for `window`, `document`, or a canvas.

**Schema changes are additive only.** Never rename a key. The canonical
component field is `atoms`, not `components`. If you add a persisted Zustand
field, it needs a store migration.

**`/api/tokens` GET is frozen and public.** POST is same-origin plus a per-slug
claim — not a user login. Durable save is GitHub (`.escala/system.json`), not
the blob. See `docs/agent-native/CONTRACTS.md` and `SECURITY.md`.

**Naming conventions per target.** Figma uses `/`, CSS uses hyphens inside
`var()`, and the JSON architecture uses dots:
`action.primary.default` → `Action/primary/default` →
`var(--color-action-primary-default)`.

**Desktop only.** The configurator is a laptop/desktop tool. Please don't send
phone editor layouts.

**No `console.log` in production code.** TypeScript is strict; avoid `any`
unless the compiler genuinely leaves no alternative.

## Licensing rules for dependencies

The project is MIT (see `LICENSE`), and incoming contributions are accepted
under the same terms. Two dependency rules keep that true:

**`apca-w3` and `colorparsley` must stay test-only.** They are imported by
`src/lib/__tests__/apca.test.ts` and nowhere else. `colorparsley` is AGPL-3.0
and `apca-w3` carries a limited W3 license; importing either from `src/` would
pull them into the distributed bundle and impose those terms on the whole
application. `src/lib/color/apca.ts` is our own implementation, verified against
these packages in tests. That is the arrangement — please don't collapse it.

**New dependencies need a permissive license.** MIT, ISC, BSD, or Apache-2.0.
If you add one under Apache-2.0 or BSD, add its attribution to `NOTICE`. Anything
copyleft (GPL, AGPL, LGPL) is a non-starter for runtime code; if you believe a
test-only exception is warranted, raise it in an issue first.

## Where things live

`AGENTS.md` is the router — it maps "what am I trying to change" to the one file
you should read. `docs/agent-native/CONTRACTS.md` lists what must not break.
`CLAUDE.md` is a deep product reference; read the section you need rather than
the whole thing.

## Commits and sign-off

We use a Developer Certificate of Origin instead of a CLA. Sign your commits:

```bash
git commit -s -m "your message"
```

That adds a `Signed-off-by` line, which certifies you wrote the change or
otherwise have the right to submit it under the MIT license.

## What we'd rather not merge

Style Dictionary or Terrazzo as the pipeline, Storybook, a second token
vocabulary living beside the semantic roles, a phone configurator, or a rewrite
of the docs into a single file. If you think one of these is genuinely right,
open an issue and make the case before writing the code.
